# CAIRN Remediation — a knowledge-integrity score you can *move*

The Integrity Report is not a vanity metric. It responds to real fixes, so it
works as a KPI: remediate the knowledge base, and the number climbs. This demo
scores the same policy library **before** and **after** its defects are fixed.

Both runs use **adjudication**, so the contradiction penalty reflects *confirmed*
conflicts (a local model classifies each candidate `contradict` / `duplicate` /
`related`), not mere topical overlap. Everything ran locally against Ollama;
nothing left the machine.

Reproduce:

```
MODEL_BASE_URL=http://localhost:11434/v1 MODEL_NAME=gemma4:latest \
MODEL_EMBED=nomic-embed-text EMBEDDINGS=on node examples/remediation-report.mjs
```

The single **confirmed contradiction** (two controlled documents in conflict)
carried the heaviest penalty — 15 points — exactly as it should: an
authoritative-vs-authoritative conflict is the worst kind of integrity failure.

## What was remediated

1. **The confirmed contradiction — reconciled.** `records-management-standard.md`
   said client records are kept **3 years**; `data-retention-policy.md` said **7
   years**. Fix: the standard no longer restates the period — it **defers to the
   Data Retention Policy** as the single source of truth ("where they appear to
   differ, the Data Retention Policy governs"). The conflict is gone, and the two
   documents are no longer near-duplicates.
2. **The broken reference — resolved.** `data-classification-policy.md` cited a
   `[[Cryptographic Key Management Standard]]` that did not exist — a control
   pointing at a missing control. Fix: the standard was **authored** (it now
   exists and is itself controlled), so the reference resolves.
3. **The orphan — filed.** `unfiled-meeting-notes.md` linked to nothing and nothing
   linked to it. Fix: its action items were **filed into the library** with links
   to the Vendor Risk, Access Control, and Records Management policies, so it is
   reachable.
4. **The stale note — retired.** `archive/legacy-retention-note-2019.md` was a
   2019 `DRAFT` still carrying `TODO`/`FIXME` markers. Fix: the superseded working
   note was **removed** from the live library.

you can act on**: it went from C to A because the knowledge base genuinely got
better, and every step is a hashed, reproducible artifact. That is the difference
between a dashboard and a control.
